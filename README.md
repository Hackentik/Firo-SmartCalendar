# Firo SmartCalendar

**Веб-приложение для бронирования переговорных комнат в офисе**

Календарь с недельным и месячным видом, конфликт-проверка занятости в реальном времени,
модерация регистрации администратором, роли администратора и обычного сотрудника.

## Возможности

- 📅 **Месячный и недельный календарь** с навигацией вперёд/назад, подсветкой
  сегодняшнего дня и кликом по ячейке для быстрого создания брони
- ✅ **Модерация регистрации администратором** — новый сотрудник может войти
  в систему только после того, как администратор одобрит его заявку; заявку
  можно отклонить или заблокировать уже одобренного пользователя в любой момент
- 🏢 **Публичный каталог комнат** — вместимость, оборудование и бронирование
  в один клик, доступно всем сотрудникам, не только админам
- ⏱ **Проверка занятости в реальном времени** (AJAX) при выборе времени и комнаты
- 👥 **Управление участниками** встречи с предупреждением о превышении вместимости
- 🎨 **Цветовая маркировка комнат** — брони на календаре подсвечиваются цветом своей комнаты
- ♾️ **Комнаты без ограничения вместимости** — для актовых залов и подобных пространств
- 📤 **Экспорт брони в `.ics`** — добавление встречи в Outlook / Google Calendar / Apple Calendar
- 🔍 **API поиска свободных комнат** по времени и минимальной вместимости
- 🔐 **Роли администратора и сотрудника** — управление комнатами и пользователями
  доступно только администраторам
- 🛡️ CSRF-защита форм, хеширование паролей, секретный ключ через переменные окружения

## Технологии

## Быстрый старт

```bash
# 1. Клонируем репозиторий
git clone https://github.com/Hackentik/firo-smartcalendar.git
cd firo-smartcalendar

# 2. Создаём виртуальное окружение
python3 -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate

# 3. Устанавливаем зависимости
pip install -r requirements.txt

# 4. (опционально) задаём секретный ключ для разработки
export FIRO_SECRET_KEY="какой-нибудь-случайный-ключ"

# 5. Запускаем
python app.py
```

Приложение поднимется на `http://127.0.0.1:5000`. База `firo_calendar.db`
создастся автоматически при первом запуске.

> Первый зарегистрированный пользователь **автоматически становится администратором**
> и входит сразу. Все последующие регистрации попадают в очередь на модерацию —
> зайдите в **Управление → Пользователи**, чтобы одобрить или отклонить заявку.

### Переменные окружения

| Переменная            | По умолчанию                     | Назначение                          |
|------------------------|-----------------------------------|--------------------------------------|
| `FIRO_SECRET_KEY`      | `dev-only-change-me-in-production` | Секретный ключ Flask — **обязательно** задать своё значение в продакшене |
| `FIRO_DATABASE_URI`    | `sqlite:///firo_calendar.db`      | Строка подключения к БД (можно указать PostgreSQL/MySQL) |

## Маршруты / API

| Метод | Путь                                   | Описание                              | Доступ       |
|-------|------------------------------------------|----------------------------------------|--------------|
| GET/POST | `/register`                           | Регистрация (заявка уходит на модерацию) | все        |
| GET/POST | `/login`                              | Вход (заблокирован для неодобренных)   | все          |
| GET   | `/calendar?view=month\|week`             | Календарь                              | одобрен      |
| GET   | `/rooms`                                 | Каталог комнат                         | одобрен      |
| GET   | `/bookings`                              | Список бронирований                    | одобрен      |
| GET/POST | `/booking/new`                        | Создание брони                         | одобрен      |
| GET/POST | `/booking/<id>/edit`                  | Редактирование брони                   | автор / админ |
| POST  | `/booking/<id>/delete`                   | Удаление брони                         | автор / админ |
| GET   | `/booking/<id>/export.ics`               | Экспорт брони в `.ics`                 | автор / админ |
| GET/POST | `/admin/rooms`, `/admin/rooms/new`, `/admin/rooms/<id>/edit` | Управление комнатами | админ |
| GET   | `/admin/users`                           | Управление пользователями и заявками   | админ        |
| POST  | `/admin/users/<id>/approve`              | Одобрить заявку / разблокировать       | админ        |
| POST  | `/admin/users/<id>/reject`               | Отклонить заявку / заблокировать       | админ        |
| POST  | `/admin/users/<id>/toggle_admin`         | Назначить/снять права администратора   | админ        |
| GET   | `/api/check_availability`                | AJAX-проверка занятости слота          | одобрен      |
| GET   | `/api/find_available_rooms`              | Поиск свободных комнат по времени/вместимости | одобрен |

## Роли и права

- **Администратор** — одобряет или отклоняет заявки на регистрацию, управляет
  комнатами, назначает других администраторов, редактирует и удаляет любые
  бронирования.
- **Сотрудник** — после одобрения администратором может создавать бронирования,
  редактировать и удалять только свои, видеть каталог комнат и общий календарь.
- **Заявка на рассмотрении / отклонённый пользователь** — не может войти в
  систему до решения администратора (даже зная правильный пароль).

## Известные ограничения

- Проверка занятости комнаты (`SELECT`, затем `INSERT`) не обёрнута в блокировку
  на уровне БД — при одновременном бронировании одного и того же слота двумя
  пользователями в одну миллисекунду теоретически возможна гонка. Для
  продакшена с высокой нагрузкой стоит добавить транзакцию с блокировкой строк
  (`SELECT ... FOR UPDATE` в PostgreSQL) или уникальный индекс на уровне БД.
- Если обновляете базу с более ранней версии проекта — удалите старый
  `firo_calendar.db` перед первым запуском (или сделайте миграцию), иначе
  новые колонки (`capacity` как nullable, `approval_status` у пользователей)
  не появятся в существующей таблице.
